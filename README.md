논문을 찾고, 모으고, 읽고, 분석하고, 원고를 쓰고, 그림을 그리는 일과 실험실 기록을 한 화면에서 하는 연구용 웹 페이지입니다.

설치할 것이 없고, 파일 하나(`index.html`)로 돌아갑니다. 서버도 로그인도 없습니다.

## 처음 쓰는 방법

1. 위 주소를 크롬이나 엣지에서 엽니다.
2. 처음 뜨는 창에 **사이트 이름**과 **내 연구 주제**를 적고 저장합니다. 연구 주제는 요약, 리서치, 검색 순위, 저널 필터에 쓰입니다.
3. **문헌 검색** 탭에서 영문 키워드로 논문을 찾고, 마음에 드는 논문을 라이브러리에 담습니다. PDF가 있으면 **라이브러리** 탭에 끌어다 놓아도 됩니다.
4. AI 기능(요약, 번역, 리서치 도구, 원고 다듬기, 그림)을 자동으로 쓰려면 설정에 API 키를 넣습니다. 아래 [AI 연결](#ai-연결)을 보세요. 키가 없어도 복사·붙여넣기 방식으로 쓸 수 있습니다.

> 어디서부터 해야 할지 모르겠다면 **홈의 질문창**에 하려는 일을 적어 보세요.
> 예를 들어 "in vitro CKD 모델로 섬유화 기전을 보고 싶어"라고 쓰면, 어느 탭과 어느 DB를 어떤 순서로 쓰면 되는지 단계별로 안내합니다.

### 관계도
- 논문 한 편을 중심으로 선행 연구, 후속 연구, 비슷한 연구를 한 장에 그립니다.
- 여러 논문을 함께 놓고 놓친 핵심 논문을 찾고, 내 라이브러리를 키워드 지도로 봅니다.

### DB 조회 (사이트 안 조회 34종 + 분야별 바로가기 127곳)
- **질문으로 찾기:** 질문 한 줄을 쓰면 AI가 맞는 DB를 1~3개 골라 조회하고, 그 결과를 근거로 답합니다. 어느 DB를 어떤 검색어로 찾았는지도 보여 줍니다.
- **DB 고르기 — 분야별:** 맨 위 조회칸에 유전자·화합물 이름 등을 넣고 DB를 고릅니다. 최근 조회를 다시 볼 수 있고, 같은 검색어로 관련 DB에 넘길 수도 있습니다.
  - **분야 버튼 12개:** AI·데이터, 로봇·기계, 반도체·양자, 전기화학·전지, 수소·에너지, 환경·기후, 소재·화학, 의과학·생명, 의·약학, 기초과학(물리·화학·생명·지구), 천문·우주, 공통(국내 연구정보·특허·데이터 보관소)
  - 분야를 고르면 **사이트 안에서 바로 조회**되는 DB와 **다른 사이트 바로가기**가 그 분야로 좁혀집니다.
  - 바로가기 중 🔍 표시가 붙은 곳은 조회칸에 넣은 말로 그 사이트의 검색 결과가 바로 열립니다. (예: DrugBank, GTEx, AlphaFold DB, NASA ADS, SIMBAD, RISS, DBpia, Google Patents, Zenodo)
  - '데이터베이스 찾기' 칸으로 DB 이름을 찾습니다.
- **Curieus 연동:** [Curieus](https://curieus.net/)는 구조 예측, 도킹, 분자동역학(MD), 단백질 디자인, scRNA-seq 분석을 코드 없이 돌리는 분석 플랫폼입니다.
  - **결과에서 넘기기:** UniProt 결과의 단백질 서열, PDB 결과의 PDB ID, PubChem 결과의 SMILES 옆에 Curieus 링크가 붙습니다. 누르면 값이 클립보드에 복사되고 Curieus 분석 화면이 열립니다.
  - **Curieus 연결 (시험 기능):** 설정에 Curieus API 키(마이페이지에서 발급)를 넣으면 DB 조회 화면에서 Curieus 도구 목록을 불러와 실행할 수 있습니다. 작업 제출처럼 크레딧이 쓰일 수 있는 도구는 한 번 더 눌러야 실행됩니다. claude.ai 안에서는 외부 연결이 막혀 있으니 내려받은 HTML이나 GitHub 사이트에서 쓰세요.

## 2. 모으고 읽기 — 라이브러리

### 넣기와 정리
- PDF, Word, 한글(HWPX), PPT, 엑셀, CSV를 **라이브러리 탭**에 끌어다 놓거나 '논문 추가'로 넣습니다.
  - 넣은 파일은 바로 저장되어 곧장 열어 볼 수 있습니다.
  - 서지정보·요약·연구 노트·핵심 용어는 Claude가 뒤에서 한 편씩 씁니다.
  - 그동안 다른 논문을 읽거나 다른 탭에서 작업해도 됩니다. 화면 왼쪽 아래에 진행 표시가 뜹니다.
  - 한 편에 3분이 넘으면 멈추고 알려 줍니다. 그때는 '다시 요약'을 누르면 됩니다.
- 그림·표를 자동으로 추출하고, 그래프에서 수치를 읽어 표로 만듭니다.
- 즐겨찾기, 읽기 상태(읽을 것·읽는 중·다 읽음), 읽기 노트, 용어집을 씁니다.

### 분류하기
| 방법 | 설명 |
|---|---|
| **내 폴더** | 직접 만드는 폴더 트리입니다. 하위 폴더를 몇 단계든 만들 수 있습니다. 상위·하위는 연결선으로 보이고, ▾/▸로 접고 폅니다. 논문이나 폴더를 끌어다 놓아 옮기고, 체크한 뒤 '폴더로 옮기기'나 서지정보의 '내 폴더' 칸으로도 옮깁니다. |
| **자동 분류 규칙** | 폴더에 단어를 적어 두면(예: kidney, AKI) 제목·키워드·저널·초록에 그 단어가 있는 새 논문이 자동으로 그 폴더에 들어갑니다. 이미 있는 논문에도 한 번에 적용할 수 있습니다. |
| **묶음** | 같은 논문에서 나온 본문, 보충자료, 발표자료, 데이터를 한 묶음으로 묶어 대표 자료 아래에 함께 보여 줍니다. DOI나 파일 이름이 같은 자료는 자동으로 추천합니다. |
| **그림·표 꺼내기** | 논문 속 그림과 표를 그 논문의 묶음 자료로 꺼내 따로 열고, 폴더에 넣고, 표는 CSV로 받습니다. 꺼낸 자료는 참고문헌·내보내기·리서치에 섞이지 않습니다. |
| **프로젝트** | 실험실 탭의 프로젝트와 같은 목록입니다. 한 곳에서 프로젝트를 고르면 라이브러리·리서치·실험실이 함께 바뀝니다. |
| **주제 폴더** | AI가 정한 주제로 자동 분류합니다. '폴더 다시 정리'로 한 번에 다시 나눌 수 있습니다. |

- 폴더를 고르면 위쪽 '서지 도구'·'내보내기'와 아래 '보이는 N편 모두 → 리서치로'가 그 폴더 기준으로 동작합니다.
- 목록 칸 너비는 오른쪽 가장자리를 끌어 조절합니다. 두 번 누르면 원래대로 돌아갑니다.
- **중복 합치기:** 같은 논문이 두 번 이상 들어가면 안내가 떠서 **하나로 합칠** 수 있습니다.
  - 메모·태그·하이라이트·질문·폴더·실험노트 연결이 모두 남은 하나로 모입니다.
  - DOI만 같은 다른 파일(본문과 보충자료)은 지우지 않고 한 묶음으로 묶습니다.

### 읽기
| 기능 | 설명 |
|---|---|
| 원문 읽기 | PDF를 띄워 놓고 설명, 번역, 질문을 합니다. 답변의 쪽 버튼을 누르면 근거 문장을 표시합니다. 다섯 가지 색 형광펜을 쓰고, 누르면 지울 수 있습니다. 참고문헌도 찾습니다. |
| 이어 읽기 | 최근에 연 논문과 읽던 쪽을 홈에 띄우고, 누르면 그 쪽부터 다시 엽니다. |
| 실험노트 연결 | 실험노트에서 참고 논문으로 걸어 둔 논문은 논문 화면에 '이 논문을 참고한 실험노트'로 보입니다. |

### 서지 도구
- RIS, BibTeX, EndNote, PubMed(nbib), CSL-JSON을 가져오고 내보냅니다.
- 인용 양식 12가지를 씁니다: APA, Vancouver, AMA, Nature, Science, Cell, ACS, Wiley, RSC, Elsevier, IEEE, Harvard.
- 원고 인용, 중복 정리, 철회·정정 확인도 여기서 합니다.
- 내보내기: 정리본 ZIP(이름 바꾼 원본 + 요약 노트 + 그림·표), 엑셀, CSV, BibTeX

## 3. 분석하기 — 리서치

## 4. 쓰기 — 원고

- 섹션별로 작성하고, 본문 중간에 표·그림·파일을 넣습니다.
- 써 둔 원고(Word, PDF, 한글)를 섹션별로 나눠 가져옵니다.
- 라이브러리 논문을 `[@키]`로 바로 인용합니다.
- 섹션 단위로 AI 다듬기·번역·점검을 하고, 버전을 저장하고, 완성본을 미리 봅니다.
- 인용과 참고문헌이 들어간 Word로 저장합니다.
- 원고 하나로 근거 대조, 통계 점검, 동료 심사, 저널 추천을 이어서 실행합니다.

### PaperOrchestra 방식으로 쓰기

Google Cloud AI Research의 [PaperOrchestra](https://arxiv.org/abs/2604.05018)(Song 외, 2026)가 쓰는 '일을 나눠 맡기는' 원고 쓰기 절차를 브라우저에서 돌아가게 옮겼습니다. 원고 화면 오른쪽의 **'PaperOrchestra 방식으로 쓰기'**를 누르면 열립니다.

| 단계 | 하는 일 |
|---|---|
| 넣을 것 | 아이디어(무엇을, 왜, 핵심 주장), 실험 기록(조건·결과·숫자), 투고 지침(선택). 실험 기록은 **실험노트에서 가져오기**로 원고와 같은 프로젝트의 노트를 한 번에 불러올 수 있습니다. |
| ① 개요 | AI 한 번으로 제목, 이야기 흐름, 그림 계획, 서론·선행연구 계획(검색어 포함), 섹션 계획, **채워야 할 정보**(빠진 대조군·n·통계 등)를 세웁니다. |
| ② 그림 계획 | 계획된 그래프는 데이터를 **그래프 도구**로 바로 넘기고, 개념도는 설명을 복사해 일러스트레이터에서 그립니다. |
| ③ 서론·선행연구 | 라이브러리에 담은 논문 가운데 주제와 가까운 것(이미 인용한 논문, 같은 프로젝트 논문 우선, 최대 30편)만 `[@키]`로 인용해 Introduction과 Related Work를 씁니다. 목록 논문의 90% 이상을 반영하는 것이 목표이고, 반영 비율과 목록에 없는 키를 표시합니다. 논문이 부족하면 개요의 검색어로 문헌 검색에서 더 담습니다. |
| ④ 나머지 섹션 | 초록, 방법, 결과, 고찰, 결론, 그림 설명을 **한 번에** 써서 앞뒤가 맞게 합니다. 표는 실험 기록의 값을 그대로 옮깁니다. |
| ⑤ 가상 심사로 다듬기 | 심사위원 역할의 AI가 6개 항목(독창성, 타당성, 명료성, 중요성, 선행연구, 구성·표현)과 종합 점수(0~100)를 매기고 고칠 점을 냅니다. 고친 원고를 다시 심사해 **점수가 오를 때만 채택**하고, 점수가 떨어지거나 실험 기록에 없던 숫자가 생기면 되돌리고 멈춥니다(최대 3번). 점수 흐름과 남은 지적을 보여 줍니다. |

- 모든 단계에서 숫자와 결과는 넣어 준 실험 기록에서만, 인용은 라이브러리 논문에서만 쓰도록 지시합니다. 기록에 없는 숫자가 나오면 빨간 글씨로 표시합니다.
- 결과는 원고마다 저장되고, **원고에 넣기**를 누르면 섹션별로 들어갑니다. 넣기 전 원고는 '버전'에 자동으로 저장됩니다.
- 원 논문의 그림 자동 생성(matplotlib)과 LaTeX 컴파일은 브라우저에서 할 수 없어, 그래프 도구·일러스트레이터로 넘기고 Word로 내보내는 방식으로 바꿨습니다.
- AI 호출은 한 번 전체를 돌릴 때 약 8~10회입니다. AI 초안이므로 숫자, 인용, 주장의 세기는 반드시 직접 확인하세요.

## 6. 실험실

탭 순서: **프로젝트 · 과제 계획·평가 · 재료 및 방법 · 세포 관리 기록부 · 동물 관리 기록부 · 실험노트 (합성, 세포, 동물 등) · 실험 일정**

| 화면 | 할 수 있는 일 |
|---|---|
| 프로젝트 | 프로젝트마다 이름과 색을 등록하고, 모든 기록을 프로젝트별로 걸러 봅니다. 요약 카드에 남은 일정, 실험노트, 기다리는 발주, 세포주·바이알, 동물 계통·마릿수, 물품, 과제 문서가 나옵니다. |
| 과제 계획·평가 | 연구계획서와 연차·최종보고서를 항목별로 씁니다. 연구비 표와 추진 일정표를 자동으로 계산하고, 공고문의 평가 기준에 맞춰 점수표, 약점, 예상 질문을 만듭니다. 파일 여러 개를 합치거나 새 양식으로 재구성할 수 있고, **사진이나 스캔한 PDF**도 AI가 글자를 옮겨 불러옵니다. |
| 재료 및 방법 → 물품 목록 | 시약 라벨이나 거래명세서 사진을 읽어 물품명, 제조사, 카탈로그, Lot, CAS를 저장합니다. Materials 문장, Key Resources Table, 표준 프로토콜을 만듭니다. **유효기한이 지났거나 30일 안에 끝나는 물품**과 **재고 부족으로 표시한 물품**을 위에 모아 보여 주고, 바로 발주 요청을 만듭니다. |
| 재료 및 방법 → 발주 기록 | 물품·동물·세포 발주를 요청 → 발주 → 입고로 관리합니다. **입고 처리하면 종류에 따라 물품 목록·세포 관리 기록부·동물 관리 기록부에 자동으로 들어갑니다.** 이미 있는 것은 새로 만들지 않고 연결만 합니다. **연구비 집계**에서 과제·계정별, 프로젝트별 금액을 합하고 과제 계획의 연구재료비와 비교합니다. |
| 세포 관리 기록부 | 세포주, 계대, 남은 바이알, 보관 위치, 마이코플라스마 검사, 꺼낸 기록을 남깁니다. 바이알이 2개 이하이거나, **계대 한도(기본 P20)**에 가깝거나 넘었거나, **마이코플라스마 검사가 90일 넘게 지났으면** 표시합니다. 세포주별 **표준 프로토콜**(해동·배양·계대·동결·품질 관리·Methods 문장)을 AI가 씁니다. |
| 동물 관리 기록부 | 계통, 종, 성별, 마리 수, 입고일·주령, 사육 위치, 실험군, 공급처, 동물실험 승인번호(IACUC), 건강 관찰을 기록합니다. **체중을 날짜별로 적으면 그래프**로 보여 주고, 첫 기록보다 15% 넘게 줄면 경고, 20%면 인도적 종료 기준 안내를 띄웁니다. **승인 마릿수 관리**에서 승인번호별로 쓴 마릿수·남은 수·승인 기간을 봅니다. 동물 **표준 프로토콜**(입고·순화, 사육, 투여·채혈, 인도적 종료 기준, ARRIVE 항목을 담은 Methods 문장)도 씁니다. |
| 실험노트 (합성, 세포, 동물 등) | 분류별 칸에 기록하고, 서식(템플릿)으로 새 노트를 만듭니다. 물품 목록에서 시약을 넣고, 참고한 라이브러리 논문을 연결합니다. **이 실험에서 쓴 것**에 세포 바이알이나 동물을 고르면 기록부의 수량이 그만큼 줄고 서로 연결됩니다(되돌리기 가능). Methods 문장으로 다듬어 원고에 넣고, Word·PDF로 모아 받습니다. |
| 실험 일정 | 월 달력에서 반복 일정을 관리합니다. 날짜를 누르면 그날의 계획·노트·발주·세포 동결·동물 입고 기록을 함께 보고, 계획에서 바로 실험노트를 씁니다. 캘린더(.ics)로 내보낼 수 있습니다. |

**기록에 공통으로 되는 것** (세포·동물 관리 기록부, 발주 기록, 실험노트, 실험 일정)
- **사진·명세서로 등록:** 거래명세서, 견적서, 라벨, 케이지 카드, 손글씨 노트, 일정표 사진이나 스캔 PDF를 AI가 읽어 칸을 채웁니다.
  - 한 장에 물품이 여러 개면 물품마다 기록을 만들고, 원본 사진도 붙입니다.
  - 추가 양식 안에서는 '📷 사진·명세서로 칸 채우기'로 빈 칸만 채웁니다.
  - 화면에 사진을 끌어다 놓아도 됩니다.
- **파일·사진 붙이기:** 등록할 때나 나중에 그림, PDF, 마크다운, 텍스트, 엑셀, 워드 등을 붙입니다. 끌어 놓기와 붙여넣기도 됩니다. 마크다운·텍스트는 그 자리에서 '내용 보기'로 읽습니다.
- **마크다운 파일로 등록:** .md·.txt 파일을 가져오거나 끌어다 놓으면 내용을 읽어 칸을 채웁니다.
  - 읽는 모양: `# 제목`, `- **분류**: 세포`, `날짜: 2026-11-18`, 2칸짜리 표, `## 목적`·`## 절차`·`## 결과` 같은 소제목
  - 여러 파일을 한꺼번에 넣으면 파일마다 기록을 하나씩 만듭니다.
  - 이미 저장된 기록에 붙이면 빈 칸만 채웁니다.
- **중복 합치기:** 같은 기록이 여러 번 있으면 안내가 떠서 하나로 합칠 수 있습니다. 물품 목록도 같습니다.
- **엑셀로 내보내기**와 **프로젝트별 거르기**가 모든 기록에서 됩니다.

**내보내기**
- 실험노트, 과제 문서, 평가, 프로토콜은 Word(.docx), PDF, Markdown으로 받을 수 있습니다.
- 한글에서는 Word 파일을 그대로 엽니다.
- 한글 파일(.hwpx) 내보내기는 아직 시험판입니다.

## AI 연결

AI 기능은 설정에 넣은 **본인 API 키**로 실행됩니다. 키는 본인 브라우저에만 저장되고 다른 곳으로 가지 않습니다. 키처럼 생기지 않은 값(띄어쓰기·줄바꿈이 섞인 값 등)은 요청에 넣지 않습니다.

| 키 | 쓰이는 곳 | 발급처 |
|---|---|---|
| Anthropic API 키 | 요약, 번역, 질문, 리서치 도구, 원고 다듬기, 벡터 모식도, 사진·명세서 읽기, 과제 문서 초안과 평가, 세포·동물 표준 프로토콜 | console.anthropic.com |
| Google AI API 키 | 이미지 생성(Google). Anthropic 키가 없으면 요약·분석도 이 키로 실행 | aistudio.google.com |
| OpenAI API 키 | 이미지 생성(OpenAI) | platform.openai.com |
| Unpaywall 이메일 (키 아님) | 원문 오픈액세스 찾기. 비우면 OpenAlex 정보로 찾음 | unpaywall.org/products/api |
| GtoPdb API 키 | 표적–리간드 약리 (2026년 8월 말부터 키 필요) | guidetopharmacology.org |
| Curieus API 키 | DB 조회의 Curieus 연결 (시험 기능) | curieus.net 마이페이지 |
| OpenAlex, Semantic Scholar 키 | 검색이 막히거나 느릴 때만 (선택) | 각 서비스 |

- **Google 모델 이름은 적지 않아도 됩니다.** 비워 두면 쓸 수 있는 모델을 자동으로 고릅니다. 적어 둔 모델이 종료됐거나 이름이 틀리면 다른 모델로 이어서 쓰고 알려 줍니다.
- **키가 하나도 없어도 쓸 수 있습니다.** AI가 필요한 곳에서 **복사·붙여넣기 방식**이 뜹니다. 프롬프트를 Claude나 다른 AI 대화창에 붙여 넣고, 답을 다시 붙여 넣으면 됩니다.
- API 사용료는 각 회사가 본인 계정에 청구합니다. ChatGPT나 Claude 구독과는 별개입니다.
- 검색, 관계도, 서지 가져오기·내보내기, 그래프와 통계, 패널 조립은 AI 없이 됩니다.

## 자료 저장과 개인정보

- 모든 자료는 **이 주소를 연 브라우저 안에만** 저장됩니다. 논문, 폴더, 보고서, 원고, 그림, 실험실 기록, 설정이 모두 그렇습니다. 다른 사람과 섞이지 않고, 운영자도 볼 수 없습니다.
- **직접 삭제해야만 사라집니다.** 저장에 실패하면 이유를 알려 줍니다.
- **다른 기기나 브라우저로 옮기기:** 설정의 **파일까지 백업 (ZIP)** → 새 기기에서 **백업 가져오기**를 합니다.
  - ZIP에는 PDF 원문, 그림, 붙인 사진·파일, 내 폴더까지 들어갑니다.
  - **글만 백업 (JSON)**은 가볍지만 파일은 빠집니다.
- **설정은 백업에 들어가지 않습니다.** 사이트 이름, 연구 주제, API 키는 설정의 **설정을 코드로 복사**로 옮깁니다. 이 코드에는 API 키가 들어 있으니 다른 사람에게 보내지 마세요.
- 같은 주소라도 사람마다, 기기마다, 브라우저마다 자료가 따로 보입니다. GitHub 주소, 내려받은 파일, claude.ai 화면도 서로 저장 공간이 다릅니다. 자동 동기화는 없습니다.
- 브라우저의 사이트 데이터를 지우면 자료도 지워집니다. 가끔 백업을 받아 두세요.
- AI 기능에 논문 본문이나 원고를 쓰면 그 내용이 해당 AI 회사(Anthropic, Google, OpenAI)로 전송됩니다. 미공개 원고나 보안이 필요한 자료는 소속 기관의 규정을 먼저 확인하세요.
- 검색어와 DOI는 논문 DB(OpenAlex, Crossref 등)로 전송됩니다.

## 알아 둘 점

- **일부 DB는 브라우저에서 바로 연결되지 않습니다.**
  - 이 사이트는 서버 없이 브라우저에서 DB 서버로 직접 요청합니다. 그래서 브라우저 요청을 받지 않는 DB(CORS 미허용)는 조회에 실패합니다.
  - 내려받은 파일(file://)로 열면 거절하는 곳이 더 많습니다. 가능하면 GitHub Pages 주소로 여세요.
  - 실패한 DB는 화면에 뜨는 바로가기로 찾으면 됩니다.
  - PROTAC-DB와 KPMP는 공개 API가 없어 바로가기로 연결합니다.
- **AI가 만든 내용은 틀릴 수 있습니다.** 요약, 근거 문장, 증거 표, 그림에서 읽은 수치는 원문으로 확인하고 쓰세요.
- **프로토콜, 과제 문서 초안, 평가는 AI가 쓴 초안입니다.** 농도와 조건은 제조사 설명서·분양처 데이터시트로, 비목과 상한은 공고문으로 확인하세요.
- **사진·명세서 읽기**에는 이미지를 볼 수 있는 AI(Anthropic 또는 Google 키)가 필요합니다. AI가 읽은 값이니 저장 전에 확인하고, 노란 줄로 표시된 칸은 꼭 직접 확인하세요.
- **동물 프로토콜·체중 경고·승인 마릿수**는 기록을 돕는 기능입니다. 실제 기준은 기관 동물실험윤리위원회(IACUC) 승인 프로토콜과 수의사 지침을 따르세요.
- **연구비 집계**는 금액 칸의 숫자를 읽어 합한 참고값입니다. 정산은 기관 연구비 시스템으로 확인하세요.
- **고IF 저널 기본 표**는 JCR 2026(2025 JIF) 값을 손으로 옮긴 것이라 오류가 있을 수 있습니다. 종합지와 주요 분야 대표지 100여 개만 들어 있습니다.
  - JCR 전체 목록은 Clarivate 유료 데이터라 배포할 수 없습니다.
  - 기관 계정으로 내보낸 파일을 '저널 관리'에서 올리세요.
- **도핑 범주**는 약리 분류로 추정한 것입니다. 확정 판정이 아니니 WADA 금지목록 원문으로 확인하세요.
- **인용 양식**은 학술지 논문 기준으로 직접 짠 것입니다. 투고 전에 저널 규정과 대조하세요.
- **AI로 만든 그림**은 저널에 따라 제한하거나 표기를 요구합니다.
- **철회 확인**은 DOI가 있는 논문만 됩니다. 데이터베이스에 반영되기 전의 최신 철회는 놓칠 수 있습니다.
- 처음 열 때 PDF·Word·엑셀 처리 라이브러리를 인터넷에서 불러옵니다.
- 크롬과 엣지 최신 버전에서 확인했습니다. 휴대폰에서도 열리지만, 원문 읽기와 원고 작성은 큰 화면이 편합니다.

## 내 것으로 따로 올리기

1. 이 저장소의 `index.html`을 내려받습니다.
2. 본인 GitHub에 Public 저장소를 만들고 `index.html`을 올립니다.
3. **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 고르고 저장합니다.
4. 1~2분 뒤 `https://<내아이디>.github.io/<저장소이름>/`으로 열립니다.

파일을 내려받아 브라우저로 직접 열어도 같은 기능이 됩니다. 다만 파일로 연 것과 주소로 연 것은 저장 공간이 달라서 자료가 서로 보이지 않습니다.

## 만든 방식과 출처

브라우저에서만 돌아가는 단일 HTML 파일입니다. 서버, 데이터베이스, 로그인 기능이 없습니다.

**연결하는 공개 서비스**

OpenAlex · Europe PMC · PubMed · Crossref · Semantic Scholar · PubChem · UniProt · ClinicalTrials.gov · NCBI E-utilities(Gene, Nucleotide, ClinVar, dbSNP, GEO) · Ensembl · RCSB PDB · Reactome · KEGG · NCI GDC · cBioPortal · Open Targets · Cellosaurus · Antibody Registry · Alliance of Genome Resources · openFDA · ChEMBL · g:Profiler · STRING · Human Protein Atlas · CZ CELLxGENE · IUPHAR/BPS Guide to PHARMACOLOGY · Unpaywall · CDK Depict(구조 그림)

**쓰는 오픈소스 라이브러리**

PDF.js · mammoth.js · JSZip · SheetJS · PptxGenJS

**참고한 작업 방식**

- 리서치 도구와 검색 절차는 scholar-megasearch, paper-curation, academic-research-skills, scientific-agent-skills, science-skills, autoresearch, k-skill, hwpx, searchinfohwpx 스킬의 절차를 브라우저에서 돌아가게 옮겼습니다.
- 이미지 생성의 계획 → 그리기 → 검토 흐름은 PaperBanana 방식을 따랐습니다.
- 원고의 'PaperOrchestra 방식으로 쓰기'는 PaperOrchestra 논문(Song, Song, Pfister, Yoon, arXiv:2604.05018, 2026)과 이를 스킬로 옮긴 [ar9av/PaperOrchestra](https://github.com/Ar9av/PaperOrchestra)의 단계 구성과 채택·되돌림 규칙을 참고해 새로 작성했습니다.

이 사이트는 위 서비스나 Zotero, EndNote, ResearchRabbit, BioRender, FigureLabs, Photopea, Clarivate(JCR), PROTAC-DB, KPMP와 제휴 관계가 없습니다.
