## 처음 쓰는 방법

1. 위 주소를 크롬이나 엣지에서 엽니다.
2. 처음 뜨는 창에 **사이트 이름**과 **내 연구 주제**를 적고 저장합니다. 연구 주제는 요약, 리서치, 검색 순위, 저널 필터에 쓰입니다.
3. **문헌 검색**에서 영문 키워드로 논문을 찾아 라이브러리에 담습니다. 가지고 있는 PDF는 **라이브러리**에 끌어다 놓습니다.
4. AI 기능을 자동으로 쓰려면 설정에 API 키를 넣습니다([AI 연결](#ai-연결)). 키가 없어도 복사·붙여넣기 방식으로 쓸 수 있습니다.

> 어디서부터 해야 할지 모르겠다면 **홈의 질문창**에 하려는 일을 적어 보세요.
> 예: "세포 모델로 질환 기전을 보고 싶어" → 어느 탭과 어느 DB를 어떤 순서로 쓰면 되는지 단계별로 안내합니다.

### 관계도

- 논문 한 편을 중심으로 선행 연구, 후속 연구, 비슷한 연구를 한 장에 그립니다.

### DB 조회

화면은 위에서부터 **조회칸 → 데이터베이스 찾기·연결 점검 → 분야 버튼 → 사이트 안에서 바로 조회 → 다른 사이트 바로가기 → Curieus 연결** 순서입니다.

- **질문으로 찾기:** 질문 한 줄을 쓰면 AI가 맞는 DB를 1~3개 골라 조회하고, 그 결과를 근거로 답합니다.
- **분야 버튼 12개:** AI·데이터, 로봇·기계, 반도체·양자, 전기화학·전지, 수소·에너지, 환경·기후, 소재·화학, 의과학·생명, 의·약학, 기초과학, 천문·우주, 공통. 분야를 고르면 두 목록이 모두 그 분야로 좁혀집니다.

**BLAST와 NCBI DB**

- **BLAST:** 서열(FASTA 또는 문자만), UniProt 번호(예: P04637), NCBI 번호(예: NM_000546)를 넣으면 EMBL-EBI의 BLAST로 비슷한 단백질을 찾아 일치율·정렬 길이·E-value·비트 점수 표로 보여 줍니다. 번호를 넣으면 서열은 알아서 받아 옵니다.
  - 단백질 서열은 blastp, 염기서열은 번역해서 단백질과 비교(blastx)합니다. 기본 대상은 UniProtKB/Swiss-Prot이고, 끝에 `| pdb`를 붙이면 PDB 구조, `| uniprot`을 붙이면 UniProtKB 전체에서 찾습니다.
  - 보통 30초~3분 걸리고, 기다리는 동안 경과 시간이 표시됩니다.
  - EBI가 요청자 이메일을 요구하므로 설정의 **Unpaywall 이메일** 칸을 채워야 합니다.
  - 결과 아래에 EBI 전체 결과 보기, NCBI BLAST에서 다시 돌리기(서열이 채워진 채로 열림) 링크가 붙습니다. 염기서열끼리 비교(blastn)는 NCBI BLAST 링크로 하세요.
  - UniProt 결과와 GenBank·RefSeq·NCBI Protein 결과 옆에도 **이 사이트에서 BLAST**와 **NCBI BLAST** 버튼이 붙습니다.
- **NCBI 전체 DB에서 건수 보기:** 검색어 하나로 NCBI의 DB 31곳(PubMed, PMC, Gene, Nucleotide, Protein, Structure, SRA, GEO, ClinVar, dbSNP, dbVar, MedGen, OMIM, PubChem 등)에 각각 몇 건이 있는지 많은 순서로 보여 줍니다. 이 사이트에서 바로 조회되는 DB는 **사이트에서 보기**로 이어집니다. NCBI 요청 한도 때문에 10초쯤 걸리고, 설정에 NCBI API 키를 넣으면 3~4초로 줄어듭니다.
- **결과를 실험노트에:** 모든 DB 조회 결과 아래의 **실험노트에 붙이기**로 고른 실험노트의 '결과·관찰' 칸 끝에 표 그대로 붙이거나, 새 실험노트(분석·기타)를 만듭니다. AI 해석을 받았으면 함께 들어갑니다.
- **NCBI DB 바로 조회:** Protein, Structure, Conserved Domains, Taxonomy, Assembly, MedGen, OMIM, GTR, dbVar, BioProject, BioSample, SRA, PMC, Bookshelf, MeSH를 사이트 안에서 표로 봅니다.

**Curieus 연동** — [Curieus](https://curieus.net/)는 구조 예측, 도킹, 분자동역학(MD), 단백질 디자인, scRNA-seq 분석을 코드 없이 돌리는 분석 플랫폼입니다.

- **결과에서 넘기기:** UniProt의 단백질 서열, PDB ID, PubChem의 SMILES 옆에 Curieus 링크가 붙습니다. 누르면 값이 복사되고 Curieus 분석 화면이 열립니다.
- **Curieus 연결 (시험 기능):** 설정에 Curieus API 키를 넣으면 DB 조회 화면에서 Curieus 도구를 불러와 실행합니다. 크레딧이 쓰일 수 있는 도구는 한 번 더 눌러야 실행됩니다. claude.ai 안에서는 외부 연결이 막혀 있으니 내려받은 HTML이나 GitHub 사이트에서 쓰세요.

## 모으고 읽기 — 라이브러리

### 넣기

- PDF, Word, 한글(HWPX), PPT, 엑셀, CSV를 끌어다 놓거나 '논문 추가'로 넣습니다.
- 넣은 파일은 바로 열어 볼 수 있고, 서지정보·요약·연구 노트·핵심 용어는 AI가 뒤에서 한 편씩 씁니다. 그동안 다른 작업을 해도 됩니다(왼쪽 아래 진행 표시).
- 그림·표를 자동으로 꺼내고, 그래프에서 수치를 읽어 표로 만듭니다.
- 즐겨찾기, 읽기 상태(읽을 것·읽는 중·다 읽음), 읽기 노트, 용어집을 씁니다.

### 정리

| 방법 | 설명 |
|---|---|
| 내 폴더 | 하위 폴더를 몇 단계든 만드는 폴더 트리. 연결선으로 보이고 ▾/▸로 접고 폅니다. 끌어다 놓거나 '폴더로 옮기기'로 옮깁니다. |
| 자동 분류 규칙 | 폴더에 단어(예: kidney, AKI)를 적어 두면 그 단어가 있는 새 논문이 자동으로 들어갑니다. |
| 묶음 | 본문·보충자료·발표자료·데이터처럼 같은 논문에서 나온 자료를 한 묶음으로 보여 줍니다. |
| 그림·표 꺼내기 | 논문 속 그림·표를 따로 열고 폴더에 넣고, 표는 CSV로 받습니다. |
| 프로젝트 | 실험실의 프로젝트와 같은 목록. 한 곳에서 고르면 라이브러리·리서치·실험실이 함께 바뀝니다. |
| 주제 폴더 | AI가 정한 주제로 자동 분류합니다. |
| 중복 합치기 | 같은 논문이 두 번 이상 들어가면 하나로 합칩니다. 메모·하이라이트·폴더·실험노트 연결이 모두 남습니다. |

### 읽기와 서지

- **원문 읽기:** PDF를 띄워 놓고 설명·번역·질문. 답변의 쪽 버튼을 누르면 근거 문장을 표시합니다. 형광펜 5색.
- **이어 읽기:** 최근에 연 논문과 읽던 쪽을 홈에 띄웁니다.
- **실험노트 연결:** 실험노트에서 참고 논문으로 건 논문은 논문 화면에도 보입니다.
- **서지 도구:** RIS, BibTeX, EndNote, PubMed(nbib), CSL-JSON 가져오기·내보내기. 인용 양식 12가지(APA, Vancouver, AMA, Nature, Science, Cell, ACS, Wiley, RSC, Elsevier, IEEE, Harvard). 중복 정리, 철회·정정 확인.
- **내보내기:** 정리본 ZIP(이름 바꾼 원본 + 요약 노트 + 그림·표), 엑셀, CSV, BibTeX.

## 분석하기 — 리서치

**1. 대상 고르기** (검색에서 고른 논문, 검색 결과 TOP 20, 라이브러리에서 고른 논문, 프로젝트 논문, 첨부 파일) → **2. 도구 고르기** → **3. 실행**. 결과는 보고서에 자동 저장되고 Word·PPT·엑셀·Markdown으로 내보냅니다.

| 묶음 | 도구 |
|---|---|
| 읽고 종합 | 문헌 리뷰, WHY/HOW/WHAT 비교, 연구 동향 타임라인, 비판적 읽기, 증거 표, 동향 보고서, 저널클럽 발표 초안 |
| 선별·검증 | **체계적 문헌고찰(PRISMA 2020)**, 팩트체크, 인용 검증(Crossref), 인용 근거 대조(원문 구절), 통계·보고 지침 점검 |
| 아이디어·설계 | 가설 생성, 실험 설계 점검, 소크라테스 대화 |
| 쓰기·심사 | 초록·서론 초안, 동료 심사 패널, 심사 답변서, 투고 저널 추천, 한국어 글 다듬기, 자동 개선 루프 |

### 체계적 문헌고찰 (PRISMA 2020)

1. **기준 정하기:** 연구 질문(PICO), 포함·제외 기준을 적고 대상을 고릅니다(리서치 1번 대상, 라이브러리 전체, 고른 논문, 폴더, 프로젝트). DOI·제목이 같은 중복은 자동으로 셉니다.
2. **제목·초록 선별:** AI가 기준에 따라 포함·보류·제외와 이유를 제안하고, 직접 바꿉니다. 애매하면 보류로 넘깁니다.
3. **원문 적격성:** 원문을 읽고 포함·제외·원문 없음으로 판단합니다. 제외 사유는 흐름도에 사유별로 묶입니다.
4. **흐름도·내보내기:** PRISMA 2020 흐름도(SVG·PNG), 판정표(CSV), 보고서 저장, 선별 과정 문단을 원고 Methods에 넣기.

AI 선별은 제안일 뿐입니다. 보고 기준은 두 명 이상의 독립 선별을 권장합니다.

## 쓰기 — 원고

### 기본

- 섹션별로 쓰고, 본문 중간에 표·그림·파일을 넣습니다. 써 둔 원고(Word, PDF, 한글)를 섹션별로 나눠 가져옵니다.
- 라이브러리 논문을 `[@키]`로 인용하면, 내보낼 때 번호나 (저자, 연도)와 참고문헌 목록으로 바뀝니다.
- 버전 저장(최근 8개)과 되돌리기, 완성본 미리보기.

### 섹션 AI 도구

| 도구 | 하는 일 |
|---|---|
| 다듬기 · 번역 · 줄이기 · 이어 쓰기 · 논리 점검 | 학술 영어로 다듬기, 한↔영 번역, 20% 줄이기, 다음 문단 쓰기, 흐름과 근거가 약한 곳 점검 |
| AI 문체 걷어내기 | 'delve', 'pivotal', 'plays a crucial role', 인용 없는 'studies have shown', 줄표 남용 같은 표현을 섹션 위에 **AI 문체 신호 n개**로 표시하고, 사실·숫자·인용은 그대로 둔 채 학술 문체로 고칩니다. |
| 여러 안 겨루기 | 간결형·이야기형·심사 대비형 세 안을 쓰고, 이름을 가린 채 AI 심판이 순위와 섞을 점을 냅니다. 고른 안으로 바꾸면 바꾸기 전 상태가 버전에 저장됩니다. |

### 초안 쓰기 (PaperOrchestra 방식)

Google Cloud AI Research의 [PaperOrchestra](https://arxiv.org/abs/2604.05018)(Song 외, 2026)처럼 일을 나눠 원고를 씁니다.

| 단계 | 하는 일 |
|---|---|
| 넣을 것 | 아이디어, 실험 기록(**실험노트에서 가져오기** 가능), 투고 지침 |
| ① 개요 | 제목, 이야기 흐름, 그림·문헌·섹션 계획, 채워야 할 정보(빠진 대조군·n·통계 등) |
| ② 그림 계획 | 그래프 데이터는 그래프 도구로, 개념도 설명은 일러스트레이터로 |
| ③ 서론·선행연구 | 라이브러리 논문만 인용(목표: 목록 논문의 90% 이상 반영). 반영 비율과 목록에 없는 키를 표시 |
| ④ 나머지 섹션 | 초록·방법·결과·고찰·결론·그림 설명을 한 번에 써서 앞뒤가 맞게 |
| ⑤ 가상 심사로 다듬기 | 6개 항목 점수로 최대 3번 고치고, **점수가 오를 때만 채택**. 떨어지거나 기록에 없던 숫자가 생기면 되돌림 |

숫자와 결과는 실험 기록에서만, 인용은 라이브러리 논문에서만 쓰도록 하고, 기록에 없는 숫자가 나오면 빨간 글씨로 표시합니다. **원고에 넣기** 전 원고는 버전에 자동 저장됩니다. 한 번 전체를 돌리면 AI를 8~10번 부릅니다.

### 점검·투고 준비·내보내기

- **이 원고로 점검:** 인용 근거 대조, 인용 검증, 통계·보고 점검, 동료 심사 패널.
- **투고 준비:** 투고 저널 추천, 심사 답변서, 한국어 글 다듬기.
- **Word로 저장:** 인용·참고문헌·그림이 들어간 Word.
- **투고용 Word:** 제목 쪽(저자·소속·교신저자 빈칸, 본문 단어 수), 2배·1.5배 줄 간격, 줄 번호, 쪽 번호, 그림 설명·참고문헌 새 쪽, 글꼴(Times New Roman, Arial, Calibri, 맑은 고딕). 그림은 본문에서 빼고 표시만 남깁니다.

## 실험실

탭 순서: **프로젝트 · 과제 계획·평가 · 재료 및 방법 · 세포 관리 기록부 · 동물 관리 기록부 · 실험노트 (합성, 세포, 동물 등) · 실험 일정**. 탭 줄 오른쪽에 **실험도구모음 바로가기**가 있습니다.

### 프로젝트

- 이름과 색을 정하면 모든 기록을 프로젝트별로 걸러 봅니다. 카드에 남은 일정, 실험노트, 기다리는 발주, 세포·바이알, 동물 계통·마릿수, 물품, 과제 문서가 나옵니다.
- **로드맵:** 최종 목표에서 거꾸로 단계를 나누고 단계마다 '꼭 있어야 할 결과'와 할 일을 적습니다. **기록으로 검증하기**를 누르면 실험노트·일정·발주·기록부를 보고 각 결과에 근거가 있는지 표시하고 다음 할 일을 알려 줍니다. 할 일은 실험 일정에 바로 넣습니다.
- **목표 같이 정하기:** 목표가 막막하면 AI가 보기 있는 질문을 하나씩 던지고, 답이 모이면 접근안 2~3개를 장단점과 함께 냅니다.

### 과제 계획·평가

연구계획서와 연차·최종보고서를 항목별로 씁니다. 연구비 표와 추진 일정표를 자동 계산하고, 공고문의 평가 기준으로 점수표·약점·예상 질문을 만듭니다. 파일 여러 개를 합치거나 새 양식으로 재구성할 수 있고, 사진이나 스캔한 PDF도 글자를 옮겨 불러옵니다.

### 재료 및 방법

| 화면 | 할 수 있는 일 |
|---|---|
| 물품 목록 | 시약 라벨·거래명세서 사진을 읽어 물품명, 제조사, 카탈로그, Lot, CAS 저장. Materials 문장, Key Resources Table, 표준 프로토콜. **유효기한 지남·30일 안에 만료·재고 부족** 물품을 위에 모아 보여 주고 바로 발주 요청 |
| 발주 기록 | 물품·동물·세포 발주를 요청 → 발주 → 입고로 관리. **입고하면 종류에 따라 물품 목록·세포·동물 관리 기록부에 자동으로 들어감**(이미 있으면 연결만). **연구비 집계**로 과제·계정별, 프로젝트별 금액을 합하고 과제 계획의 연구재료비와 비교 |

| 기록부 | 할 수 있는 일 |
|---|---|
| 세포 관리 기록부 | 세포주, 계대, 남은 바이알, 보관 위치, 마이코플라스마 검사, 꺼낸 기록. 바이알 2개 이하, **계대 한도(기본 P20)** 근접·초과, **마이코 검사 90일 경과**를 표시. 세포주별 **표준 프로토콜**(해동·배양·계대·동결·품질 관리·Methods 문장) |

### 실험노트 · 실험 일정

- **QR 코드로 바로 찾기:** 실험도구모음에서 만든 라벨의 QR을 휴대폰으로 찍으면 허브가 열리면서 그 이름을 물품 목록·세포/동물 기록부·실험노트에서 찾아 줍니다.
- **홈에서 실험도구모음 보기:** 허브 홈에 실험도구모음의 타이머(진행 중·끝난 것), 아직 안 보낸 사진, 진행 중인 프로토콜이 함께 뜹니다(같은 GitHub 주소에서 열었을 때).
- **사진 메모 받기:** 실험도구모음의 '사진 메모'로 보낸 사진은 실험노트에 그대로 붙습니다.
- **실험도구모음에서 받기:** 실험도구모음의 '실험노트로 보내기'로 보낸 계산 결과가 오른쪽 아래에 뜹니다. 새 실험노트로 만들거나 기존 노트의 '결과·관찰' 칸에 붙입니다(같은 GitHub 주소에서 열었을 때).
- **실험노트:** 분류별 칸, 서식(템플릿), 물품 목록에서 시약 넣기, 참고 논문 연결. **이 실험에서 쓴 것**에 세포 바이알이나 동물을 고르면 기록부 수량이 줄고 서로 연결됩니다(되돌리기 가능). Methods 문장으로 다듬어 원고에 넣고, Word·PDF로 모아 받습니다. 버튼은 검색칸 아래 한 줄로 있습니다.
- **실험 일정:** 월 달력, 반복 일정. 날짜를 누르면 그날의 계획·노트·발주·세포 동결·동물 입고를 함께 보고, 계획에서 바로 노트를 씁니다. 캘린더(.ics) 내보내기.

- **사진·명세서로 등록:** 거래명세서, 견적서, 라벨, 케이지 카드, 손글씨 노트, 일정표 사진이나 스캔 PDF를 AI가 읽어 칸을 채웁니다. 한 장에 여러 품목이면 품목마다 기록을 만들고 원본도 붙입니다. 화면에 끌어다 놓아도 됩니다.

## 홈 · 보고서 · 설정

- **홈:** 찾는 순서 안내, 이어 읽기, 오늘의 실험, 실험실 카드(기다리는 발주, 바이알 부족, 유효기한·재고 부족, 체중 감소 경고), 즐겨찾기, 새 논문 알림. 검색창 위에 **실험도구모음**과 **전공 학습실** 바로가기가 있습니다.
- **백업 알림:** 자료가 브라우저에만 저장될 때(내려받은 파일, GitHub 사이트) 2주 넘게 백업하지 않으면 홈에 알림이 뜨고, 바로 ZIP으로 백업합니다.
- **보고서:** 리서치 결과를 폴더·종류·즐겨찾기로 정리하고 내보냅니다.
- **설정:** 사이트 이름, 연구 주제, API 키, 테마, 바로가기 버튼, 백업과 설정 옮기기.
- **Claude 스킬로 내보내기:** 이 허브의 작업 방식(논문 요약, 실험노트 정리, 원고 다듬기 규칙, 로드맵 검증)을 SKILL.md가 든 ZIP으로 받아 Claude 앱에 스킬로 올립니다. 연구 주제와 실험노트 칸 이름만 들어가고, API 키나 기록 내용은 들어가지 않습니다.

## AI 연결

AI 기능은 설정에 넣은 **본인 API 키**로 실행됩니다. 키는 본인 브라우저에만 저장됩니다.

| 키 | 쓰이는 곳 | 발급처 |
|---|---|---|
| Anthropic API 키 | 요약, 번역, 질문, 리서치, 원고 도구, 벡터 모식도, 사진·명세서 읽기, 과제 문서, 프로토콜, PRISMA 선별 | console.anthropic.com |
| Google AI API 키 | 이미지 생성(Google). Anthropic 키가 없으면 요약·분석도 이 키로 | aistudio.google.com |
| OpenAI API 키 | 이미지 생성(OpenAI) | platform.openai.com |
| Unpaywall 이메일 (키 아님) | 원문 오픈액세스 찾기(비우면 OpenAlex로), DB 조회의 BLAST(EBI가 요청자 이메일을 요구) | 본인 이메일 |
| GtoPdb API 키 | 표적–리간드 약리 | guidetopharmacology.org |
| Curieus API 키 | DB 조회의 Curieus 연결 (시험 기능) | curieus.net 마이페이지 |
| NCBI API 키 (선택) | DB 조회의 NCBI 요청 한도를 초당 3번에서 10번으로 (NCBI 전체 DB 건수 보기가 빨라짐) | ncbi.nlm.nih.gov 계정 설정 |
| OpenAlex, Semantic Scholar 키 | 검색이 막히거나 느릴 때만 (선택) | 각 서비스 |

- **Google 모델 이름은 적지 않아도 됩니다.** 비워 두면 쓸 수 있는 모델을 자동으로 고르고, 적은 모델이 종료됐으면 다른 모델로 이어 씁니다.
- **키가 없어도 됩니다.** AI가 필요한 곳에서 복사·붙여넣기 방식이 뜹니다. 프롬프트를 AI 대화창에 붙여 넣고 답을 다시 붙여 넣으면 됩니다.
- claude.ai 화면에서 열면 키 없이 Claude가 바로 동작합니다.
- API 사용료는 각 회사가 본인 계정에 청구합니다. ChatGPT·Claude 구독과는 별개입니다.
- 검색, DB 조회와 BLAST, 관계도, 서지 가져오기·내보내기, 그래프와 통계, 패널 조립, PRISMA 흐름도는 AI 없이 됩니다.

## 자료 저장과 개인정보

- **어디에 저장되나:** GitHub 주소나 내려받은 파일로 열면 **그 브라우저 안에만** 저장됩니다. claude.ai 화면에서 열면 본인 claude.ai 계정에 저장됩니다. 세 곳은 서로 저장 공간이 달라 자료가 공유되지 않습니다.
- **직접 삭제해야만 사라집니다.** 저장에 실패하면 이유를 알려 줍니다.
- **옮기기·백업:** 설정의 **파일까지 백업 (ZIP)** → 새 기기에서 **백업 가져오기**. ZIP에는 PDF 원문, 그림, 사진·파일, 폴더까지 들어갑니다. **글만 백업 (JSON)**은 가볍지만 파일이 빠집니다.
- **설정은 백업에 들어가지 않습니다.** 사이트 이름, 연구 주제, API 키는 **설정을 코드로 복사**로 옮깁니다. 이 코드에는 API 키가 들어 있으니 다른 사람에게 보내지 마세요.
- 브라우저의 사이트 데이터를 지우면 자료도 지워집니다. 백업 알림이 뜨면 받아 두세요.
- AI 기능에 논문 본문이나 원고를 쓰면 그 내용이 해당 AI 회사(Anthropic, Google, OpenAI)로 전송됩니다. 미공개 원고나 보안이 필요한 자료는 소속 기관 규정을 먼저 확인하세요.
- 검색어와 DOI는 논문 DB(OpenAlex, Crossref 등)로 전송됩니다.

## 알아 둘 점

- **일부 DB는 브라우저에서 바로 연결되지 않습니다.** 서버 없이 브라우저가 DB에 직접 요청하므로, 브라우저 요청을 받지 않는 곳(CORS 미허용)은 실패합니다. 내려받은 파일(file://)로 열면 거절하는 곳이 더 많으니 가능하면 GitHub 주소로 여세요. 실패하면 화면의 바로가기로 찾으면 됩니다.
- **AI가 만든 내용은 틀릴 수 있습니다.** 요약, 근거 문장, 증거 표, 그림에서 읽은 수치, 사진에서 읽은 값은 원문으로 확인하고 쓰세요.
- **프로토콜·과제 문서·원고 초안은 AI 초안입니다.** 농도와 조건은 제조사·분양처 데이터시트로, 비목과 상한은 공고문으로 확인하세요.
- **동물 기능(프로토콜, 체중 경고, 승인 마릿수)**은 기록을 돕는 기능입니다. 실제 기준은 기관 IACUC 승인 프로토콜과 수의사 지침을 따르세요.
- **연구비 집계**는 금액 칸의 숫자를 읽어 합한 참고값입니다. 정산은 기관 연구비 시스템으로 확인하세요.
- **고IF 저널 기본 표**는 JCR 값을 손으로 옮긴 100여 개 저널이라 오류가 있을 수 있습니다. 전체 목록은 기관 계정으로 내보낸 파일을 '저널 관리'에서 올리세요.
- **도핑 범주**는 약리 분류로 추정한 것이라 확정 판정이 아닙니다.
- **인용 양식**은 직접 짠 것이니 투고 전에 저널 규정과 대조하세요.
- **AI로 만든 그림**은 저널에 따라 제한하거나 표기를 요구합니다.
- **철회 확인**은 DOI가 있는 논문만 되고, 아주 최근 철회는 놓칠 수 있습니다.
- 처음 열 때 PDF·Word·엑셀 처리 라이브러리를 인터넷에서 불러옵니다.
- 크롬과 엣지 최신 버전에서 확인했습니다. 휴대폰에서도 열리지만 원문 읽기와 원고 작성은 큰 화면이 편합니다.

## 내 것으로 따로 올리기

1. 이 저장소의 `index.html`을 내려받습니다.
2. 본인 GitHub에 Public 저장소를 만들고 `index.html`을 올립니다.
3. **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 고르고 저장합니다.
4. 1~2분 뒤 `https://<내아이디>.github.io/<저장소이름>/`으로 열립니다.

파일을 내려받아 브라우저로 직접 열어도 같은 기능이 됩니다. 다만 파일로 연 것과 주소로 연 것은 저장 공간이 달라 자료가 서로 보이지 않습니다.

**업데이트:** 새 `index.html`을 같은 이름으로 다시 올리면 됩니다. 쓰는 사람들의 자료와 설정은 그대로 남습니다. 예전 화면이 보이면 Ctrl+Shift+R(맥은 Cmd+Shift+R)로 새로고침하세요.
