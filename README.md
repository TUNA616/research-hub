# 나의 연구 허브

논문을 찾고, 읽고, 분석하고, 원고를 쓰고, 그림을 그리는 일과 실험실 기록(프로젝트, 재료, 세포 stock, 발주, 실험노트, 실험 일정, 과제 계획서·보고서)을 한 화면에서 하는 연구용 웹 페이지입니다.
설치할 것이 없고, 파일 하나(`index.html`)로 돌아갑니다.

**바로 쓰기:** https://tuna616.github.io/research-hub/

---

## 처음 쓰는 방법

1. 위 주소를 크롬이나 엣지에서 엽니다.
2. 처음 뜨는 창에 **사이트 이름**과 **내 연구 주제**를 적고 저장합니다. 연구 주제는 요약, 리서치, 검색 순위에 쓰입니다.
3. 문헌 검색 탭에서 영문 키워드로 논문을 찾고, 마음에 드는 논문을 라이브러리에 담습니다.
4. AI 기능(요약, 번역, 리서치 도구, 원고 다듬기)을 자동으로 쓰려면 설정에 API 키를 넣습니다. 아래 "AI 연결"을 보세요.

회원 가입이나 로그인은 없습니다. 자료는 모두 쓰는 사람의 브라우저에 저장됩니다.

### ⑥ 실험실 (실험실(프로젝트, 재료, 방법, 일정))
| 화면 | 할 수 있는 일 |
|---|---|
| 프로젝트 | 프로젝트마다 이름과 색(견본 24가지 또는 원하는 색)을 등록. 재료, 세포, 발주, 실험노트, 일정, 과제 문서를 프로젝트별로 걸러 보기. 원고, 라이브러리 논문, 보고서도 프로젝트에 연결. 프로젝트별 요약 카드(남은 일정, 실험노트, 기다리는 발주, 세포, 재료, 과제 문서). 이름을 바꾸면 기록에도 함께 반영 |
| 과제 계획·평가 | 연구계획서, 연차보고서, 최종보고서를 항목별로 작성. 본문 중간에 표, 그림, 파일 넣기(엑셀·한글 표를 붙여넣으면 표로 바뀜, 표 안에 커서를 두고 다시 누르면 고치기, 그림은 붙여넣기·끌어 놓기도 됨, 아래에 미리보기). 메모로 초안 쓰기, 다듬기, 줄이기, 평가 기준에 맞춰 보완(AI가 고쳐 써도 넣어 둔 표·그림·파일은 그대로 남음). 연차보고서는 해당 기간의 실험노트를 근거로 사용. 연구비 표(비목 × 연차, 합계와 비율 자동 계산)와 추진 일정표(월·분기, 실험 일정에서 가져오기). 공고문과 평가 기준을 붙여 넣으면 그 기준으로 점수표, 약점과 고칠 방법, 예상 질문. 파일 여러 개를 올려 단순히 합치거나 새 양식으로 재구성 |
| 재료 | 시약 라벨이나 거래명세서 사진을 올리면 물품명, 제조사, 카탈로그 번호, Lot, CAS 등을 읽어 저장(사진 보정, 구간 확대, 불확실한 칸 재확인). Materials 문장, Key Resources Table, 물품별 표준 프로토콜 제안 |
| 세포 stock | 세포주, 계대, 남은 바이알 수, 보관 위치, 꺼낸 기록. 2개 이하면 표시 |
| 발주 기록 | 물품·동물·세포 발주를 요청 → 발주 → 입고로 관리. 입고 예정일이 지나면 표시. 입고된 것은 재료 목록이나 세포 stock으로 바로 넘기기 |
| 실험노트 | 합성, 세포, 동물, 분석으로 나눠 분류별 칸에 기록. 목적·절차·결과 칸 중간에 표, 그림, 파일 넣기. 서식(템플릿)으로 새 노트 만들기(기본 서식: CCK-8, Western blot, 동물 투여·관찰, 합성)와 내 노트를 서식으로 저장. 사진은 장수 제한 없이 붙이기(파일 선택, 붙여넣기, 끌어 놓기). 재료 목록에서 쓴 시약 넣기, 복사해서 반복 실험 노트 만들기, Methods 문장으로 다듬어 원고에 넣기(비슷한 문단이 이미 있으면 알려 줌). 노트 하나, 체크해서 고른 노트들, 또는 걸러 본 노트 전체를 사진과 함께 날짜순으로 한 Word·PDF 파일에 |
| 실험 일정 | 월 달력(일요일 빨강, 토요일 파랑, 프로젝트 색), 반복 일정, 날짜를 누르면 그날의 계획·실험노트·발주·세포 기록을 함께 보기, 계획에서 바로 실험노트 쓰기, 캘린더 파일(.ics)로 내보내기 |

홈에는 실험실 카드 세 개(일정과 실험노트, 물품과 세포 stock, 계획서와 보고서)와 오늘의 실험이 나옵니다.

**내보내기:** 실험노트, 과제 문서, 평가, 프로토콜은 Word(.docx), PDF, Markdown으로 받을 수 있습니다. 본문에 넣은 표와 그림은 Word와 PDF에 그대로 들어가고, 첨부 파일은 파일 이름으로 적힙니다(파일 자체는 화면의 '받기'나 ZIP 백업으로 받아요). 한글(HWP)에서는 Word 파일을 그대로 열 수 있고(파일 → 불러오기), 한글에서 다시 HWP로 저장하면 됩니다. 실험노트와 과제 문서는 한글 파일(.hwpx)로도 받을 수 있지만 아직 시험판입니다: 표는 글자 줄로, 그림은 설명으로 들어가며, 한글에서 열리지 않으면 Word 파일을 쓰세요. PDF는 쪽마다 그림으로 저장되므로 PDF 안의 글자를 선택하거나 검색할 수는 없습니다.

### ⑦ 모아 두기와 설정
보고서 분류(폴더, 종류, 즐겨찾기), 홈의 즐겨찾기 모음, 다크·라이트 테마, 바로가기 버튼, 백업과 설정 옮기기.

## AI 연결

AI를 쓰는 기능은 설정에 넣은 본인 API 키로 실행됩니다. 키는 본인 브라우저에만 저장되고 이 사이트의 서버로는 가지 않습니다(이 사이트에는 서버가 없습니다).

| 키 | 쓰이는 곳 | 발급처 |
|---|---|---|
| Anthropic API 키 | 요약, 번역, 질문, 리서치 도구, 원고 다듬기, 벡터 모식도, 재료 사진 읽기, 과제 문서 초안과 평가 | console.anthropic.com |
| Google AI API 키 | 이미지 생성(Google). Anthropic 키가 없으면 요약·분석도 이 키로 실행 | aistudio.google.com |
| OpenAI API 키 | 이미지 생성(OpenAI) | platform.openai.com |
| Unpaywall 이메일 (키 아님) | DB 조회의 원문 오픈액세스 찾기. 비우면 OpenAlex 정보로 찾음 | unpaywall.org/products/api |
| GtoPdb API 키 | DB 조회의 표적–리간드 약리 (2026년 8월 말부터 키 필요) | guidetopharmacology.org |
| OpenAlex, Semantic Scholar 키 | 검색이 막히거나 느릴 때만 (선택) | 각 서비스 |

- 키가 하나도 없어도 쓸 수 있습니다. AI가 필요한 곳에서 **복사·붙여넣기 방식**이 뜨고, 프롬프트를 Claude나 다른 AI 대화창에 붙여 넣은 뒤 답을 다시 붙여 넣으면 됩니다.
- API 사용료는 각 회사가 본인 계정에 청구합니다. ChatGPT나 Claude 구독과는 별개입니다.
- 검색, 관계도, 서지 가져오기·내보내기, 그래프와 통계, 패널 조립은 AI 없이 됩니다.

## 자료 저장과 개인정보

- 논문, 보고서, 원고, 그림, 설정은 **이 주소를 연 브라우저 안에만** 저장됩니다. 다른 사람과 섞이지 않고, 운영자도 볼 수 없습니다.
- 다른 기기나 다른 브라우저에서는 보이지 않습니다. 옮기려면 설정의 **파일까지 백업 (ZIP)**으로 받아 새 기기에서 **백업 가져오기**를 합니다. ZIP에는 PDF 원문, 그림, 재료·실험노트 사진, 본문에 넣은 그림과 첨부 파일까지 들어갑니다. **글만 백업 (JSON)**은 가볍지만 파일은 빠집니다.
- 사이트 이름, 연구 주제, API 키 같은 설정은 백업에 들어가지 않습니다. 설정의 **설정을 코드로 복사**로 옮기고, 이 코드에는 API 키가 들어 있으니 다른 사람에게 보내지 마세요.
- 같은 주소라도 사람마다, 기기마다, 브라우저마다 각자의 자료가 따로 보입니다. 자동 동기화는 없습니다.
- 브라우저의 사이트 데이터를 지우면 자료도 지워집니다. 가끔 백업을 받아 두세요.
- 논문 본문이나 원고를 AI 기능에 쓰면 그 내용이 해당 AI 회사(Anthropic, Google, OpenAI)로 전송됩니다. 미공개 원고나 보안이 필요한 자료는 소속 기관의 규정을 먼저 확인하세요.
- 검색어와 DOI는 논문 DB(OpenAlex, Crossref 등)로 전송됩니다.

## 알아 둘 점

- **일부 DB는 브라우저에서 바로 연결되지 않습니다.** 이 사이트는 서버 없이 브라우저에서 DB 서버로 직접 요청합니다. 그래서 브라우저 요청을 받지 않는 DB(CORS 미허용)는 조회에 실패합니다. 내려받은 파일(file://)로 열면 요청에 주소가 없어(Origin: null) 거절하는 곳이 더 많으니, 가능하면 GitHub Pages 주소(https://…)로 여세요. DB 조회 탭의 '연결 점검'으로 확인할 수 있고, 실패한 DB는 화면에 뜨는 바로가기 링크로 찾으면 됩니다.

- **AI가 만든 내용은 틀릴 수 있습니다.** 요약, 근거 문장, 증거 표, 그림에서 읽은 수치는 원문으로 확인하고 쓰세요.
- **프로토콜, 과제 문서 초안, 평가**는 AI가 쓴 초안입니다. 농도와 조건은 제조사 설명서로, 비목과 비율 상한은 공고문으로 확인하세요. 평가는 실제 선정 결과를 예측하지 않습니다.
- **재료 사진 읽기**는 이미지를 볼 수 있는 AI(Anthropic 또는 Google 키)가 필요합니다. 노란 줄로 표시된 칸은 꼭 직접 확인하세요.
- **KEGG** 등 일부 DB는 브라우저에서 직접 연결이 막힐 수 있습니다. 그때는 해당 사이트로 가는 링크가 대신 나옵니다.
- **고IF 저널 기본 표**는 JCR 2026(2025 JIF) 값을 손으로 옮긴 것이라 오류가 있을 수 있고, 종합지와 주요 분야 대표지 100여 개만 들어 있습니다. JCR 전체 목록과 IF는 Clarivate 유료 데이터라 사이트에 넣어 배포할 수 없으니, 기관 계정으로 JCR에서 내보낸 파일을 저널 관리에서 올리세요. 올린 목록은 그 브라우저에만 저장됩니다.
- **인용 양식**은 학술지 논문 기준으로 직접 짠 것입니다. 책, 학위논문, 저널별 세부 규정과는 다를 수 있으니 투고 전에 대조하세요.
- **AI로 만든 그림**은 저널에 따라 제한하거나 표기를 요구합니다. 투고 규정을 확인하세요.
- **철회 확인**은 DOI가 있는 논문만 되고, 데이터베이스에 반영되기 전의 최신 철회는 놓칠 수 있습니다.
- 처음 열 때 PDF, Word, 엑셀 처리용 라이브러리를 인터넷에서 불러옵니다. 인터넷 연결이 필요합니다.
- 크롬과 엣지 최신 버전에서 확인했습니다. 휴대폰에서도 열리지만 원문 읽기와 원고 작성은 큰 화면이 편합니다.

## 내 것으로 따로 올리기

1. 이 저장소의 `index.html`을 내려받습니다.
2. 본인 GitHub에 Public 저장소를 만들고 `index.html`을 올립니다.
3. **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 고르고 저장합니다.
4. 1~2분 뒤 `https://<내아이디>.github.io/<저장소이름>/`으로 열립니다.

파일을 내려받아 브라우저로 직접 열어도 같은 기능이 됩니다. 다만 파일로 연 것과 주소로 연 것은 저장 공간이 달라서 자료가 서로 보이지 않습니다.

### 업데이트
새 `index.html`을 같은 이름으로 다시 올리면 덮어써집니다. 쓰는 사람들의 자료와 설정은 그대로 남습니다. 예전 화면이 계속 보이면 Ctrl+Shift+R(맥은 Cmd+Shift+R)로 새로고침하세요.

## 만든 방식과 출처

브라우저에서만 돌아가는 단일 HTML 파일입니다. 서버, 데이터베이스, 로그인 기능이 없습니다.

**연결하는 공개 서비스**
OpenAlex · Europe PMC · PubMed · Crossref · Semantic Scholar · PubChem · UniProt · ClinicalTrials.gov · NCBI E-utilities(Gene, Nucleotide, ClinVar, dbSNP, GEO) · Ensembl · RCSB PDB · Reactome · KEGG · NCI GDC · cBioPortal · Open Targets · Cellosaurus · Antibody Registry · Alliance of Genome Resources · openFDA · ChEMBL · g:Profiler · STRING · Human Protein Atlas · CDK Depict(구조 그림)

**쓰는 오픈소스 라이브러리**
PDF.js · mammoth.js · JSZip · SheetJS · PptxGenJS

**참고한 작업 방식**
리서치 도구와 검색 절차는 scholar-megasearch, paper-curation, academic-research-skills, scientific-agent-skills, science-skills, autoresearch, k-skill, hwpx, searchinfohwpx 스킬의 절차를 브라우저에서 돌아가는 형태로 옮겼습니다. 이미지 생성의 계획 → 그리기 → 검토 흐름은 PaperBanana 방식을 따랐습니다.

이 사이트는 위 서비스나 Zotero, EndNote, ResearchRabbit, BioRender, FigureLabs, Photopea, Clarivate(JCR)와 제휴 관계가 없습니다.
